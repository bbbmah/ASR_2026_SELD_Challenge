# NOTES (정한 것과 기본값)

- 작업 위치: zip은 `STARSS23_datasets/`에 있었다(루트가 아님). 압축 해제·렌더링은 로컬 `C:\asrwork`, 결과만 드라이브로 복사.
- 입력 확인(검증 1): 라벨 168, FOA 168, 영상 156. 영상 없는 12개는 room21 mix001~012뿐. 오디오-영상 길이 차 최대 0.30초, 5초 넘는 불일치 없음 → 제외는 영상 없는 12개뿐(유효 156). FOA 확인됨(4ch, 24kHz).
- 라벨 끝이 오디오보다 짧은 것은 정상(끝부분 무음)이라 불일치로 보지 않았다. 라벨이 미디어보다 5초 이상 길 때만 제외 기준.
- `py360convert`는 pip 최신(1.0.4)이 생성기의 `E2PFast`와 API가 달라 깨진다 → 생성기 `requirements.txt`대로 `0.1.0`으로 내렸다. (검증 3용)
- 피치 부호: φ<0이 아래를 본다(고도 el과 같은 부호). 카메라는 세계 방위각 ψ, 고도 φ를 본다. 카메라 좌표 = (앞, 왼, 위)이고 회전은 `d_cam = (d·fwd, d·left, d·up)`.
- 공개 라벨 `azimuth`, `distance`는 정수(생성기와 같이 반올림). `onscreen`은 반올림 전 실수 각도로 계산. `distance`는 원본 단위(cm) 그대로.
- 영상 코덱: OpenCV `mp4v`(생성기와 동일). 브라우저 재생은 안 될 수 있으나 cv2/ffmpeg로는 읽힘.
- 원본 영상에서 프레임 위치는 `round(t·fps)`로 `CAP_PROP_POS_FRAMES` 탐색 후 순차 읽기.
- 클립 선택은 계획 단계(`build.py plan`)에서 라벨 30프레임 미만·피크 초과를 걸러 낸 뒤 번호를 매긴다(그래서 번호는 연속). train은 걸러진 만큼 다시 뽑고, val/test는 해당 창을 버린다.
- val 방: 라벨 프레임 비율 목표 17.5%에 가장 가까운 Tampere 1 + Sony 1 조합 → room 9 + room 22 (16.7%).
- 시드: `SEED=<비공개>`, (데이터셋, split)마다 별도 난수열. 궤적 값은 `manifest.csv`에 전부 기록.
- 파일럿: main20 train 20개, 워커 10개에서 클립당 wall 3.4초 → main20 전체(3650개) 약 3.5시간, ctrl5(약 12800개) 비슷한 규모로 추정.

- 본 생성 실측: main20 클립당 wall 3.0초, ctrl5 0.86초(워커 10). 실패 0개. 총 클립: main20 3650, ctrl5 14409.

## ctrl5 v2 / fix20 작업 (rev_Ctrl5.md)
- 지침서의 `work/DCASE2025_seld_baseline/`는 실제로는 `baseline/DCASE2025_seld_baseline/`이다.
- 옛 `ctrl5/`는 `ctrl5_v1_old/`로 이름만 바꿨다. main20 `manifest.csv`의 `start_frame` 단위는 라벨 프레임(0.1초)이었다.
- ctrl5 v2: main20 창(3650개)을 5초 4조각으로 나눠 고정 카메라로 새로 렌더링(14600개). 난수열 `[SEED=<비공개>, 3, split]`(3=ctrl5v2), 요는 조각마다 0~359 정수. 렌더링·오디오·라벨 코드는 `dsgen.py` 그대로.
- 피크 0.9999 초과로 빠진 창: train 1, val 1, test 0 → 해당 main20 클립은 `main20/_dropped/`로, ctrl5 조각은 `ctrl5/_dropped/`로 옮겼다(삭제 없음). main20 `manifest.csv`에 `dropped` 열 추가(원본은 `.bak_before_v2`). train은 다시 채우지 않았다. 남은 main20 클립: train 2999, val 123, test 526 → ctrl5 11996 / 492 / 2104.
- 옛 main20 공개 zip과 manifest_public은 `main20/_dropped/old_zips/`로 옮기고 새 목록으로 다시 만들었다.
- 라벨이 없는 조각은 헤더만 있는 csv로 두었다. 비율: train 1.31%, val 5.08%, test 1.38%.
- 확인 3 (빈 라벨): 베이스라인 `utils.load_labels`(torch 등은 가짜 모듈로 대체해 import)가 헤더만 있는 csv를 `{}`로 읽고, `metrics.py`도 크래시 없이 처리한다. 단 **정답이 없는 파일/프레임의 예측은 오검출(FP)로 세지 않는다**: `metrics.py:223`에서 `nb_ref_frames = max(frame)`(빈 파일이면 0)이고 `:120`의 `range(len(gt.keys()))`가 그 길이만큼만 돈다. 그래서 (a) 빈 정답 파일에서는 무엇을 예측해도 FP=0, (b) 마지막 정답 프레임 및 그 뒤의 예측은 평가되지 않는다. 데이터는 고치지 않았다. 베이스라인 수정 작업에서 `nb_ref_frames`를 클립 길이(50/200)로 바꿔야 한다.
- 확인 4 (채점 단위): 프레임 단위다. `metrics.py:120`이 0.1초 프레임마다 돌고, `:122`에서 클래스마다 `:124-128`로 정답/예측 존재를 판단해 TP(`:169`), FP(`:172-175`), FN(`:177`)을 프레임·클래스별로 누적한다. 소리 구간(이벤트) 단위 매칭은 없다. 점수 계산은 `compute_seld_scores`(`:64-107`).
- fix20: main20 val/test의 남은 창마다 20초 클립 1개, 요는 클립마다 0~359 정수 고정, 피치 0. 난수열 `[SEED, 4, split]`. 이름은 부모와 같다. 피크 초과 클립은 fix20에서만 빼고 `fix20/_dropped/`로 옮긴다.
- fix20 결과: 649개 렌더링(실패 0), 피크 초과로 `val_00088` 1개만 fix20에서 빠짐(`fix20/_dropped/`). 확인: 개수는 남은 main20 창 수와 같고(val 123→122, test 526), 같은 창끼리 클래스별 행 수 일치. 이후 비교는 세 데이터셋에 모두 있는 창만 쓴다. fix20·ctrl5는 비공개.
- `m.clip`은 pandas 메서드라 `m["clip"]`로 써야 한다는 점을 build_v2.py/validate_ctrl5.py에서 한 번 틀렸고 고쳤다(데이터에 영향 없음).
