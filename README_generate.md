# 데이터 생성 노트북 사용 설명서 (코랩)
2026-10-07
`colab_generate.ipynb`로 `DATA_PLAN_v2.md`의 추가 학습 데이터(시간 창, 카메라 가족, 좌우 거울)를 코랩에서 만듭니다. 생성 코드는 `build/gen_v2.py`(기존 `build/dsgen.py`의 렌더링, 오디오, 라벨 변환을 그대로 씀)입니다.

## 1. 순서

1. 드라이브의 `colab_generate.ipynb`를 코랩으로 열고 런타임을 **GPU**로 바꿉니다.
2. 셀을 위에서부터 실행합니다.
   - 1번: 드라이브 연결, 환경 확인
   - 2번: **설정 칸**
   - 3번: 원천(STARSS23 zip)을 `/content/raw`에 풀기 (세션마다 처음 한 번 5~10분)
   - 4번: 코드 불러오기
   - 5번: 창 계획 만들기 (드라이브 `plan.csv`에 저장, 다음 실행에도 같은 계획)
   - 6번: **자체 점검**(거울, 카메라 가족, GPU 렌더러, 작은 실행). `PASS`가 아니면 멈춤
   - 7번: **생성** (묶음 단위, 이어 하기)
   - 8번: 요약과 매니페스트 병합
   - 9번: 마무리(선택)
3. **첫 실행은 묶음 1개만** 만듭니다(`MAX_SHARDS = 1`). 7번 셀 끝에 묶음당 시간과 남은 시간 추정이 나옵니다. 괜찮으면 `MAX_SHARDS = 0`으로 바꿔 7번 셀을 다시 실행하세요(끝난 묶음은 건너뜁니다).
4. 세션이 끊기면 3~7번 셀을 순서대로 다시 실행하면 이어서 합니다.

## 2. 설정

| 이름 | 기본값 | 뜻 |
|---|---|---|
| `STAGE` | 1 | 단계. 단계마다 시드가 달라서 **새 창**이 만들어집니다 |
| `N_WINDOWS` | 6000 | 이 단계의 창 수 = main20 클립 수 (ctrl5 조각은 4배) |
| `SHARD_WINDOWS` | 250 | 묶음 하나의 창 수 (약 1.5GB) |
| `MAX_SHARDS` | 1 | 이번 실행에서 처리할 묶음 수, 0 = 남은 전부 |
| `RENDERER` | auto | auto / gpu / cpu |
| `WORKERS` | 0 | 0 = 자동. GPU 렌더러는 워커마다 약 2GB 메모리라 일반 램에서는 4 이하 권장 |
| `MIRROR_FRACTION` | 0.5 | 좌우 거울 창의 비율 |
| `RARE_BONUS` | True | 박수, 전화, 문, 물, 종, 노크가 든 창에 변형 1개 추가 |
| `FAMILY_MIX` | F1=0.5,F2=0.1,F3=0.1,F4=0.15,F5=0.15 | 카메라 가족 비율 |
| `FULL_VERIFY` | True | 업로드한 zip을 처음부터 끝까지 다시 읽어 검사 |

카메라 가족: F1 = 챌린지 정의(sweep), F2 느린 회전(9°/s), F3 빠른 회전(36°/s), F4 정지-회전 반복, F5 좌우 왕복. 모두 각속도 45°/s 이하이고 라벨과 무관하게 시드로만 정합니다.

## 3. 결과물 (드라이브 `generated/s{단계}/`)

| 파일 | 내용 |
|---|---|
| `plan.csv`, `plan_params.json` | 창 계획(녹음, 시작 프레임, 가족, 궤적 파라미터, 거울, 조각 고정 요)과 계획 설정 |
| `s{단계}_main20_train_p000.zip` ... | main20 클립 묶음. 압축을 풀면 `train/{video,audio,labels,meta}/train_s{단계}_NNNNN.*` (기존 데이터와 같은 구조, 같은 형식) |
| `s{단계}_ctrl5_train_p000.zip` ... | ctrl5 조각 묶음. 이름은 `train_s{단계}_NNNNN_{0..3}` (`_j`가 조각 번호, 부모 창은 이름 앞부분) |
| `s{단계}_main20_manifest_p000.csv` ... | 묶음별 매니페스트 (녹음, 시작 프레임, 가족, 거울, 궤적 파라미터 JSON) |
| `s{단계}_ctrl5_manifest_p000.csv` ... | ctrl5 조각 매니페스트 (`parent_clip`, `j`, `psi0`, `mirror`) |
| `s{단계}_{main20,ctrl5}_manifest.csv` | 8번 셀이 합친 전체 매니페스트 |
| `status.json` | 묶음별 상태(검증 결과, 피크로 버린 창, 실패, 소요 시간) |

내부용입니다. 공개 폴더(`dataset/`)에는 넣지 않았습니다.

## 4. 원칙 (이 노트북이 지키는 것)

- **val, test 방은 쓰지 않습니다.** 창은 train 방 녹음에서만 뽑습니다.
- **기존 데이터는 건드리지 않습니다(append-only).** 새 클립은 `train_s{단계}_...` 이름이라 기존과 겹치지 않습니다.
- **같은 창의 main20 클립과 ctrl5 조각은 같은 소리를 씁니다.** 거울이면 둘 다 거울입니다. 이전의 ctrl5 v2 규칙과 같습니다(조각 단위로 거르지 않음, 라벨 없는 조각 허용).
- **피크가 0.9999를 넘는 창은 통째로 버립니다**(main20과 ctrl5 양쪽에서). `status.json`에 기록됩니다.
- **검증이 끝난 묶음만 로컬에서 지웁니다**(크기, zip 목록과 CRC, 전체 읽기). 문제가 있으면 그 묶음을 로컬에 남기고 멈춥니다.
- 카메라 방향, 거울 여부는 **소리와 영상에 포함되지 않습니다.** 매니페스트와 `meta/`에만 있습니다.

## 5. 검증과 한계 (정직하게)

- **이 PC(Windows, CPU)에서 확인한 것**: 자체 점검 전부(거울 오디오 오차 0, 거울 영상 평균 차이 0.0002/255, 거울 라벨 부호와 `onscreen`, 카메라 가족 각속도 최대 40°/s, 빠른 회전의 소리 연속성, GPU 렌더러 대 CPU 렌더러 평균 차이 0.0003/255), 병렬 묶음 생성, zip과 업로드 검증, 이어 하기, 피크로 버려지는 창, 노트북 셀 코드 전체(드라이브 연결과 원천 풀기만 제외하고 하네스로 실행: `build/nb_harness.py`). 실제 크기 계획(6,000창)이 목표 개수에 수렴함도 확인(6,011창).
- **확인하지 못한 것**: 코랩 환경(드라이브 마운트, `!unzip`, 코랩의 CPU 수와 램), **실제 GPU(CUDA)에서의 GPU 렌더러**(CPU 장치로만 비교함), 코랩에서의 생성 속도. 첫 묶음으로 속도를 보고, 6번 셀의 `gpu_vs_cpu_mean_abs_diff`가 1 미만인지 확인하세요.
- **속도 추정**: 이 PC에서 측정한 단일 프로세스 값(200프레임 기준: 디코딩 2.9초, CPU 렌더링 4.6초, 인코딩 0.4초)으로 창당 CPU 약 12.8초, GPU 렌더링이면 약 3.9초로 추정했습니다. 코랩 실측이 아닙니다.
- **학습 쪽 연동은 되어 있습니다**(`baseline/seld_challenge/colab_run.ipynb`의 `train_stages`, 사용법은 `README_baseline.md` 9절). S1(5,912창)을 만들어 드라이브 `generated/s1/`에 저장되어 있습니다.
- **결정 대기 중인 것** (`DATA_PLAN_v2.md` 12절): 공개 train에 포함할지, F1 외 가족을 섞을지(`FAMILY_MIX`로 조절 가능), 평가 보강(val_x, test_x)은 아직 만들지 않았습니다.

## 6. 용량과 시간 (계획 기준)

| 단계 | 창 | main20 클립 + ctrl5 조각 | zip 용량 | 시간 커버 배수(누계) |
|---|---|---|---|---|
| 1 (6,000창) | 6,011 | 6,011 + 24,044 | 약 36GB | 약 16배 (기존 5.4배 포함) |
| 2 (+9,000창) | 약 9,000 | 9,000 + 36,000 | 약 55GB | 약 32배 |

드라이브는 5TB이고 코랩 로컬은 묶음 하나(약 1.5GB)와 원천(약 9GB)만 쓰므로 용량 문제는 없습니다.
